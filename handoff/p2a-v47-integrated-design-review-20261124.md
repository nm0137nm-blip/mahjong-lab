# P2a-v4.7 第三者設計レビュー統合決定（2026-11-24）
Claude Opus 5.5 と Gemini のユーザー提供レビューを独立に受領。両者は依頼書のみを根拠としており、コード・回答原本・CIを直接監査していない。共通結論は新設計着手のみ条件付きGO。第2往復不要。v45/v46 NO-GO、過去の合格/不合格、main、S42製品基準を変更しない。本記録は設計方針であって実装完了・事前登録の凍結・支出承認ではない。

## 統合方針
- 案C：自然日本語で具体的な比較と反転条件。predicates/effect/target/direction、語彙・接続詞のハード検査を廃止。推薦・対案・反転先は合法具体行動key（鳴き後打牌も含む）。他家3席を網羅し最重要席は同等/不明ならnull可。影響の薄い席は公開根拠を1つ添えた短文で足りる。全体の反転条件と重要席の反転条件を求め、同一条件が両方を満たせば重複不要。条件の物理的可能性、因果、結論との整合は意味評価。
- 入力は局面を一度のみ、合法手の短い辞書、候補ごとの共通事実は共有、上位の詳細化は公開決定論的な選定のみ（Mortal順位/QをStage1へ漏らさない）。全合法手の選択に必要な事実は残す。公開事実IDを席・候補・条件にスコープ付け。研究ログ/隠し牌/将来情報/対照/正解はモデル入力外。ハッシュ/versionは通信側で厳密に結び付ける。生原本は非公開/暗号化。
- 出力の骨格は recommendation, alternative, keyOpponent, explanation, opponents (seatごとのnote), flips (if,then, optional seat)。説明は比較の決め手・何を犠牲にするか・不確実性・別局面でも使える学び。冗長なcitedIds転記や同義条件の再掲は不要。最終スキーマは回帰試験前に固定。
- ハード: 完了した不正JSON、違法具体行動key、推薦=対案、不正ID、席別欄の他席専用ID、席の欠落、確定量の素数値（点/翻/符/枚/%等、漢数字・全角・万表記も対象）、確定事実矛盾や隠し情報・未校正確率の確定主張のうち機械で確実に立証できるもの。牌名・席・巡目・自然な一般表現を誤拒否しないよう負例/正例を作り、機械で確定できない数値や文脈は警告と意味評価へ。ID実在だけでは引用の意味正しさを保証しない。レンダラーで値を展開し、事実整合PASSと戦術品質UNVERIFIEDを分離する。
- 運用失敗/モデル契約失敗/意味品質の3分類。打切りは設定失敗として停止、途中文を修復/採点しない。純粋な輸送障害は事前登録で許可し、出力未閲覧かつ生成の重複リスクと費用を管理できる場合のみ同設定最大1回、全試行と欠測を記録。認定8/8完了かつ全契約PASS、初回未完了の指標も別記、再試行が初回欠測を消さない。費用上限不足なら実行前停止。
- v46 pilot81/82 入力7267/7116、出力2476/2868（推論1034/1552）。pilot82は右打切り、真の必要出力長は不明。暫定出力cap6000（観測最大2868の2倍超）、各新packetの実token countから保守上限を算定し、必要時事前登録で引き上げる。旧記録の$2.50/M入力全量cache-write扱い+$10/M出力を例示すると入力7267で$0.0781675/回、8回$0.62534（再送別・価格未再確認・承認額でない）。現行単価/tier/課金仕様・全件入力token count・再送含む最大総額を検証して用途別個別承認。出力天井を予算に合わせて削らない。実請求額照合が未済であることを維持。
- 目的関数：既定の製品ルールは赤あり25000点持ち素点、トビ/親トップ止め等の終局条件を保存。Mortal S42の順位戦向け行動を比較参照とし、素点最適を証明したとはしない。鳳凰卓級の順位判断力は別の明示された順位効用ベンチマークで検証する。順位効用を製品目的に無断変更しない。具体的順位配分は一次資料で確認・凍結するまで仮定で決めない。初期製品のS42推奨をLLMで上書きしない。目的と採点条件を問題・採点資料に同一明示。
- 診断を最優先。既出3〜4局面（pilot81および既出v45等、pilot82は打切り例と明示）で無料手動を先行、同一局面の効率比較は同一transport/model/settingsでなければ因果を断定しない。必要な場合のみ別途承認された少額API診断。盲検で有用性が対照から分離しなければ設計の構造改良を止め、コード骨格＋LLM言語化等を再検討。診断は認定に算入しない。
- 盲検：同一局面・同じ事実カード・同等文量/文体、少なくとも半数を流暢な意図的誤戦術（他家優先、因果逆転、誤結論、迎合）。一般論・移植対照も候補。開発と生成/シャッフル/採点を分離し、可能な限り同じコーチモデルの独立セッションで対照を作り、採点者以外が意図した欠陥を確認。対照のラベルと相互採点をロックまで秘匿。採点資格用の別のアンカーで誤り検出能力を先に確認し、資格未達の評価を認定に用いず、三者揃わない場合は認定保留。事前登録で資格基準、対応比較（複数なら最強の対照）、停止規則を固定。
- L4従来閾値を緩和しない：各実回答中央値>=6、6/8以上中央値>=9、弱対照が2/3から9以上を得る件数0、同一局面の対応差>=3が6/8以上。さらに1人でも重大誤りを指摘、または点差>=4なら自動合格せず根拠監査。確認された重大誤りはFAIL、未解決も保留。採点者単独分離率と一致率を併記。診断時は過半数の分離不能で停止（少数例の診断であり一般化しない）。
- 未見台帳：v46 pilot81/82は回答曝露済（82途中出力を含む）、83..88は未回答だがパネル全8件を隔離。新16対局中未選抜の残数/適格局面は要監査、未確認値を断定しない。認定は別の8対局の未見局面（立直2、副露3、打牌3、各分類に他家立直あり）を事前固定、公開hash/対局seed/過去曝露を監査。診断は既出、未見認定は使い捨て履歴・残量管理。L3.5の原型対局も別。
- 検証順：無課金準備とL3.5のMortalのみの合法対照作成（変化/維持各4クラスタ以上、別ソース）を並行 → 無料優先既出診断/早期盲検（必要なAPI診断は別承認）→ 診断終了時または停止時に第三者チェックポイント（Claudeの早い方を採用）→ 未見Stage1（実行手段は別承認、旧手動/API承認は転用不可）→ Stage1回答の早期L4匿名評価 → 両方合格後のみStability/Stage2 → L3.5のLLM意味試験 → 残余L4/最終判定。従来閾値を維持。Stage1と早期L4後のGemini推奨チェックも維持。新規有料試行ごと用途、必要性、無料代替、見込/最悪費用、回数、継続費用を明示する。
