# 麻雀LAB Phase 2.5 — Mortal-S42 AI分析・振り返り

## 初回設定
トップ画面からMortal-S42の`model.onnx`を選んでください。容量43,673,425バイト、公開済みSHA-256との一致を検証してIndexedDBに端末内保存します。すでに2.4で保存済みであれば原則として再アップロード不要です。Safariのサイトデータを消すと消える場合があります。

## 打牌ごとの分析
自分が打牌するまで推奨を表示しません。打牌後、手牌の近くに **自分の選択とS42の選択**を表示します。以前の電脳麻将CPUの参考判断は廃止しましたが、**対戦相手3人のCPUは従来の電脳麻将AIのまま**です。

「詳しく」には2タブあります。

- **牌効率・受け入れ**：自分の打牌、S42の打牌（切り牌を返した場合）、牌効率上位3種類について、打牌後の手牌、向聴数、直接有効牌の種類と見かけ上の残り枚数を比較します。S42が「リーチ」などを選んだときは、実際に切る牌を推測しません。
- **S42の定量評価**：合法手ごとのQ値、Mortal推奨度（合法手Qを温度0.1でSoftmax変換）、S42最良手と自分の行動の順位・Q値差、局面内相対差、判断指数を表示します。

### S42のQ値の数式上の分解

提供されたMortal v4 DQNの学習済みモデルはdueling networkです。

`Q(s,a) = V(s) + A(s,a) - mean_{legal} A(s,・)`

したがって、合法行動のQ値の平均は`V(s)`で、各行動の「平均からの相対優位度」は`Q(s,a)-V(s)`です。**この数式上の2項分解を実際の推論値で表示**しています。

これは「牌効率点＋守備点＋打点点」に分解できるという意味ではありません。Q値もV値も期待点数や放銃確率ではありません。局面特徴量の各項目への正確な寄与度（因果関係）はこの画面から確定できません。

## 終局後の評価

対局が終わると、S42で評価できた打牌のみについて次の独自指標を表示します。

| 指標 | 計算方法 | 注意 |
|---|---|---|
| S42一致率 | S42の最良合法行動との完全一致数÷解析済み行動数 | リーチなどの行動も含む |
| 悪手率 | **S42推奨度が5%未満の打牌数 ÷ S42で解析できた打牌数** | 温度0.1のSoftmax。鳴き・見送りは対象外、リーチ打牌は対象。5%ちょうどは悪手としない |
| S42判断指数（暫定・0〜100） | 100×(1−相対Q差)を打牌ごとに計算し平均 | 公式段位レーティングではない |

Q差が定義できない局面、S42モデル未読込、S42の合法手と選択行動を対応させられない局面は集計に含めず、件数を表示します。旧版で記録された「相対Q差30%以上」の悪手候補率を新基準の悪手率に読み替えず、旧対局の悪手率は未計測とします。

「推奨度5%未満の打牌を振り返る」で、直前の対局における悪手基準に該当する打牌を推奨度の低い順に最大25局面確認できます。自分の打牌時点の手牌、公開されていた河・副露・ドラ表示牌・点棒、S42の判断と牌効率を保存します。**他家の非公開牌・山の中身は保存しません。**

トップ画面の「計測成績」では東風／半荘別に判断指数・一致率・悪手候補率を集計します。従来の成績履歴を残しつつ、**S42評価が記録された完走の「計測用対局」だけ**がS42累計に参加します。練習対局でもその対局の終局評価・振り返りは利用可能です。

## CPUの強さについて

Phase 2.5では **S42はコーチ担当のみ**です。対戦するCPUの強さは変更していません。

S42相当のCPUへの更新は技術的に可能ですが、各AIに別々の非公開局面を保持させ、合法手・鳴き・カン・立直・推論待ちの処理を実装する必要があります。iPhoneの処理性能とゲーム進行への影響を測定した後、別リリースとして提供する予定です。

## プライバシー・費用・制限

局面分析は端末内JavaScript/WebAssembly・ONNX Runtime Webで動きます。ゲーム状態とモデルの内容を外部解析サーバーへ送信しません。静的なページとライブラリの取得・更新には通常の通信が必要です。有料契約、購入、決済は不要です。

動作確認はChromiumの375/393px画面で実施。iPhone SafariでのPhase2.5の画面操作、長時間連続対局、モデル再読込はユーザー実機での確認が必要です。
