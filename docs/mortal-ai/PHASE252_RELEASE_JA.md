# 麻雀LAB Phase 2.5.2 — S42 Safari安定化

## 今回の対象
Phase 2.5.1（東4/南4アガリ・テンパイやめ、トビ終局、Mortal推奨度5%未満の悪手率）を維持し、iPhone Safari相当のWebKit環境で本物のS42を起動して推論するまでの信頼性を改善します。

## モデルの導入
1. トップ画面から「S42モデルを取得・設定」を実行できます。ただしHugging Face側のCORS/ブラウザ制約がある場合、直接取得が失敗することがあります。
2. 直接取得が失敗した場合、画面の公式「モデル配布元」を開き、`model.onnx`（43,673,425 bytes）を端末の「ファイル」アプリに保存し、選択欄で指定してください。
3. 端末内でSHA-256 `30381bf21389e2d25d3edf48fed11bf772336ef3daeee67d1bdae7fb9dd30cb4`を照合します。WebCryptoで大容量のハッシュ計算ができない場合だけFIPS-180-4準拠の分割計算に切り替えます。照合に失敗したモデルは使用しません。
4. IndexedDBにモデルを保存できなかった場合も、検証できたモデルはそのページ内の推論に使用します。ただし再読み込み時にはモデルの再選択が必要です。
5. 推論と判断履歴は端末内に留まり、モデル重みはGitHubにコミットしません。

## S42が準備完了の場合
- 打牌した**後**に初めてS42の推奨・Q値・推奨度を表示します。
- 「S42の定量評価」タブには合法手のQ値・推奨度、選択順位・判断指数を表示します。
- 悪手率は**推奨度5%未満の評価済み打牌数÷評価済み打牌数**です（リーチを含み、鳴き・スルーは除外）。
- 未解析の局面についてはQ値や推奨度を捏造しません。

## 品質ゲート
- Node単体テスト: 麻雀エンジンの終局判定、Mortal推奨度・悪手率、WebAssemblyイベント変換に加え、純JavaScript SHA-256を標準実装と照合。
- GitHub Actions: 公式公開モデルを毎回一時取得しSHA-256確認、モバイルWebKitでローカルファイル読み込み、実モデル1打牌推論・推奨度表示、モデル再読み込みを検査。CIではモデルを成果物として公開しません。
- **実iPhone Safariの実機検証は、エミュレータ検証とは別項目**。未実施の場合は実機検証済みと表現しません。

## 継続課題
- 自動ダウンロードは外部配布元のCORS・ブラウザ制限に依存し、端末のファイル選択をフォールバックとして維持します。
- 鳴き・リーチ・カン、実戦の終局成績、長時間の東風・半荘完走、オフライン復元を今後も追跡します。
- 対戦CPUは従来の電脳麻将AIで、S42はコーチのみ。S42対戦CPU化はPhase 2.6で別途検証します。
