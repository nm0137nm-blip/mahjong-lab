# 麻雀LAB 開発方針（2026-11-20第三者検証反映）
根拠：ユーザー提供18頁の「麻雀コーチAI開発 4回答の比較整理と統合提言 実行計画確定版」。写真で判読できた内容を採用し、判読困難な数値は実験前に確認する。既存の700半荘の結果とモデルは凍結し基準として保存。製品と研究を分離し、製品は研究の終了を待たない。

| 段階 | 内容 | ゲート |
|---|---|---|
| 共通Phase 0 | 利用条件、Q・合法手・独立S42整合、再現性、4席duplicate、試験分散 | 監査証拠、固定試験計画、事前登録、必要試験数 |
| 製品P1 | OOF確率校正、Brier/log loss/AUPRC/reliability、局面内危険牌順位、条件付き失点、即時期待放銃損失 | 独立データで比較、校正・順位・誤差・不確実性を提示 |
| 製品P2 | Mortal推奨＋上位3〜5候補、決定論的事実、推定リスク・損失・不確実性、説明 | 本番推奨を上書きしない、根拠数値と文章整合 |
| 製品P2b | 説明あり/なしの学習転移パイロット | 小規模で評価、一般化を主張しない |
| 製品P3 | 反実仮想的行動整合性 | 合法な対照局面、説明根拠とMortal選択変化の一致/不一致を分離。内部因果の証明ではない |
| 研究R1 | 自作AIの損失上位100件を分類 | 牌効率/押引き/立直/鳴き/着順条件/エンジン差等、失敗原因集計 |
| 研究R2 | DAgger、再ランキング、ロールアウト | 1サイクルMME +15pt、最大2サイクル、生成2,000半荘/回、正式比較400ブロック×2方式×4席=3,200半荘/回上限 |
| 研究R3 | 継続/凍結/製品への限定導入 | 独立試験と事前登録した基準、予算内に確証なしなら結論保留で凍結 |

研究の合計上限は生成4,000半荘・正式比較6,400半荘。Mortalと標準CPU/自作AI等を分けて評価。推定したロン可能確率は実際のロン選択率と異なり、単純な他家確率和は少なくとも1人に放銃する確率ではない。一方、各家への支払いの期待値の和は支払いルール（一人ロン/複数ロン/供託等）を明示した教師定義の下で評価する。即時損失を局収支・着順効用と混同しない。生Qは点数や確率ではない。

## Phase 0 初回の具体的着手
既存独立PyTorch/native encoder/WebKitの合成fixture監査を再実行し、4ブロック×4席＋同一席再実行=20半荘の運用監査を追加する。先行実験結果からモデル選択を変更しない。山乱数をそれ以外から分離し、局・本場・発生回数のキーを使用。完全対局の独立runtimeとの整合、guard/グループ内解決、対比較ブロック差の分散推定は別工程。今回のpilotから研究の必要数を確定しない。

正式な計画v1.0のうち、運用チェックの入力・合格条件・予算は固定済み。正式な比較の例数・精度閾値は独立pilot前に定義方法を、pilot後・本試験前に数値を固定する。後から成績に合わせて変更しない。P1、研究R1のデータ取得はPhase0の監査結果を見て着手。製品公開は利用条件の確認完了までは行わない。
